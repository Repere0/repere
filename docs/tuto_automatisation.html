Poser le lanceur, la dernière fois

3 minutes
Pourquoi c'est la dernière

Le nouveau workflow ne contient plus aucune logique : il installe Python, Node et un navigateur, puis lance bash outils/pipeline.sh. Tout ce qui pourra changer demain est dans outils/, un dossier ordinaire où j'écris sans passer par toi. Ce fichier-là ne devrait plus jamais bouger.

copy /Y docs\collecte_workflow_v3.yml.txt .github\workflows\collecte.yml
findstr /C:"pipeline.sh" .github\workflows\collecte.yml
Réussi si

La seconde commande affiche une ligne. Sinon, arrête-toi et dis-le-moi.

git add -A && git commit -m "Chaine deplacee dans outils/pipeline.sh ; banc en CI" && git push

Installer la tâche horaire

30 secondes
Ce qu'elle remplace

Je peux écrire dans ton dossier mais je n'ai aucun terminal sur ta machine : je ne peux pas lancer git. C'était la dernière chose qui te restait à faire à chaque fois. pousser.bat le fait : il récupère les commits du robot, ajoute ce qui a changé, et envoie.

Double-clique installer_tache_horaire.bat, dans C:\Users\APina\repere. Aucun droit administrateur n'est nécessaire.

Réussi si

La fenêtre affiche « Tache creee : elle tournera toutes les heures. » Tu peux aussi double-cliquer pousser.bat quand tu veux, sans attendre l'heure. Il écrit tout dans journal_pousser.txt.

Ce qu'il refuse de faire

Il s'arrête, sans rien envoyer, si un fichier à envoyer porte .env, secret, token, credential, .pem ou id_rsa dans son nom, ou s'il dépasse 50 Mo. Pour retirer la tâche : desinstaller_tache.bat.

3

Les deux secrets Netlify

10 minutes, une fois
La dernière chose que je ne peux pas faire

Un jeton ne doit jamais passer par une conversation. C'est la seule étape de ce document que je ne pourrai jamais reprendre, quelle que soit la configuration.

  • Le jeton — app.netlify.com/user/applications → New access token. La valeur ne s'affiche qu'une fois.
  • L'identifiant — app.netlify.com/sites/repereapp/configuration/general → Site information → Site ID.
  • Les déposer — github.com/Repere0/repere/settings/secrets/actions → New repository secret.
NETLIFY_AUTH_TOKEN
NETLIFY_SITE_ID
Sans exception

Ces deux valeurs ne vont que dans le formulaire GitHub. Jamais dans un fichier du dépôt, jamais dans une conversation — y compris avec moi.

✓

Ce qui se passe ensuite, tout seul

tous les jours
  • 5 h 47 — le robot télécharge l'Assemblée, normalise l'agenda, décrit le schéma des scrutins.
  • Il vérifie : format, nombre de réunions, aucune donnée nominative de présence, date du jour, et qu'il reste des réunions à venir — ce dernier point attrape le gel silencieux d'une source, par exemple après une dissolution.
  • Il reconstruit le site, l'agenda du matin remplaçant la copie figée dans les 17 Mo.
  • Il éprouve : 40 contrôles dans un vrai navigateur, sur le site reconstruit. Un seul échec et rien n'est publié.
  • Il publie sur Netlify, et écrit dans le journal « publié » ou « non publié, secrets absents ».
  • Toutes les heures, ta machine envoie au dépôt ce que j'ai écrit entre-temps.

Ce que je ne peux pas automatiser, et je ne le cacherai pas

Tes secrets. Ton téléphone. Et le jugement : le jour où le banc passera au vert sur quelque chose de faux, c'est un humain qui devra le voir. Un banc vert sur une page cassée reste un banc vert.

Une réserve honnête : les trois fichiers .bat sont écrits pour Windows, mais je n'ai aucun moyen de les exécuter d'ici — mon conteneur est sous Linux. Leur structure est vérifiée, leur comportement réel ne l'est pas. Si l'un d'eux se comporte mal au premier lancement, envoie-moi journal_pousser.txt.
