Brancher le monorepo

Trois gestes, un quart d'heure. Tout le reste est déjà écrit sur ton disque.

D'abord, la bonne nouvelle : tu n'as rien à installer et rien à faire tourner sur ton PC.

Les commandes que je t'ai données hier soir étaient facultatives — c'est la chaîne GitHub qui construit et qui vérifie, sur ses propres machines. Ton PC ne sert qu'à envoyer les fichiers, comme d'habitude, avec pousser.bat.

  1. Envoyer le monorepo sur GitHub

    2 minutes · sur ton PC

    Double-clic sur pousser.bat, dans C:\Users\APina\repere. C'est exactement le geste que tu fais déjà.

    Ce que tu dois voir

    La fenêtre noire défile et se termine par OK - envoye. Elle aura envoyé le dossier mono\ et une trentaine de fichiers.

    Si tu lis REFUS : un fichier au nom suspect allait partir

    C'est arrivé le 26 août, et c'était ma faute. pousser.bat refuse tout envoi contenant un fichier dont le nom évoque un secret — et il cherchait le mot token n'importe où dans le chemin. Le monorepo apporte packages/ui/src/tokens.css, les jetons de couleur de l'interface : le garde a bloqué tous les envois pendant trois heures, sans dire lequel des fichiers posait problème.

    La version 3 de pousser.bat corrige ça : elle écarte d'abord les extensions qu'un secret ne porte jamais (.css, .js, .md…), puis applique le même contrôle au reste — un .env, un .pem ou un token.txt restent attrapés. Et elle nomme le fichier en cause. Si tu vois encore ce message, c'est que tu as l'ancienne version.

    Cet ordre-là compte.

    Il faut envoyer mono\ avant de créer le fichier de l'étape 2. Sinon la chaîne se lancera en cherchant un dossier qui n'existe pas encore sur GitHub, et elle échouera pour cette seule raison.

  2. Créer le fichier de la chaîne, sur le site de GitHub

    5 minutes · dans ton navigateur

    C'est le seul geste un peu inhabituel, et il a une raison : le dossier .github\workflows\ est protégé en écriture — je ne peux pas y déposer de fichier à distance. C'est déjà pour ça que tu avais dû coller collecte.yml à la main.

    1. Ouvre ton dépôt Repère sur github.com.
    2. Clique sur l'onglet Code, puis entre dans le dossier .github, puis workflows. Tu dois y voir collecte.yml.
    3. En haut à droite, bouton « Add file » → « Create new file ».
    4. Dans la case du nom, tape exactement : build-publish.yml
    5. Sur ton PC, ouvre docs\build_publish_workflow.yml.txt avec le Bloc-notes. Ctrl + A puis Ctrl + C pour tout copier.
    6. Reviens sur GitHub, clique dans la grande zone de texte, Ctrl + V.
    7. Descends en bas de page, bouton vert « Commit changes », puis à nouveau « Commit changes » dans la fenêtre qui s'ouvre.
    Ce que tu dois voir

    Le dossier workflows contient maintenant deux fichiers : collecte.yml et build-publish.yml.

    Si le fichier existe déjà sur GitHub.

    Tu n'as pas à le recréer : entre dedans, clique sur l'icône crayon en haut à droite, Ctrl + A pour tout sélectionner, colle la nouvelle version par-dessus, puis « Commit changes ».

    Le nom doit être exact.

    build-publish.yml — un tiret au milieu, et .yml à la fin, pas .yaml ni .txt. GitHub ignore silencieusement un fichier mal nommé : rien ne se passera, et rien ne te dira pourquoi.

  3. Lancer la chaîne à la main, une fois

    30 secondes, puis 4 minutes d'attente

    1. Sur GitHub, onglet « Actions », tout en haut.
    2. Dans la colonne de gauche, clique sur « Construire, éprouver, publier ».
    3. À droite, bouton « Run workflow » → puis le bouton vert « Run workflow ».
    4. Attends une trentaine de secondes, puis rafraîchis la page. Une ligne apparaît avec un rond jaune qui tourne.
    Ce que tu dois voir au bout de 4 à 5 minutes

    Un rond vert. En cliquant dessus puis sur l'étape « Extraire les données par département », tu dois lire departements : 104 et communes reparties : 34637. Et tout en bas de la page du run, un fichier site-monorepo à télécharger : c'est le site construit.

    Elle ne met rien en ligne, et c'est voulu.

    Ton site actuel continue d'être publié par collecte.yml, comme avant. Cette nouvelle chaîne construit et vérifie seulement. On basculera la publication quand elle aura tourné au vert plusieurs jours de suite — deux chaînes qui publient en même temps se marcheraient dessus sans que personne ne le voie.

Si le rond est rouge — les trois causes probables

Clique sur le rond rouge, puis sur l'étape qui porte une croix. Le message est en bas.

Ce que tu lisCe que ça veut direQuoi faire
Some specified paths were not resolved Le dossier mono\ n'est pas sur GitHub — la chaîne cherche un verrou qui n'y est pas encore. C'est presque toujours pousser.bat qui a refusé l'envoi. Ouvre journal_pousser.txt et regarde les dernières lignes : si tu y lis REFUS secret, prends la version 3 de pousser.bat.
No such file or directory près de mono Même cause. Même remède. Vérifie que mono apparaît dans l'onglet Code de GitHub avant de relancer la chaîne.
Dependencies lock file is not found Corrigé le 26 août : l'étape qui prépare Node cherchait le verrou à la racine du dépôt au lieu de mono\. Assure-toi d'avoir collé la dernière version de docs\build_publish_workflow.yml.txt — elle contient la ligne cache-dependency-path.
ERR_PNPM_OUTDATED_LOCKFILE mono\pnpm-lock.yaml n'a pas été envoyé, ou il est plus ancien que les package.json. Relance pousser.bat après avoir vérifié que je t'ai bien envoyé le verrou à jour.
bloc REPERE_RNE introuvable La chaîne n'a pas trouvé le fichier de l'application à la racine. Envoie-moi le message, c'est de mon côté : le chemin est à corriger.

Dans tous les cas : copie-moi les dernières lignes rouges. Je ne devine pas, je lis.

Facultatif — le faire tourner sur ton PC

Tu n'en as pas besoin. Ça sert seulement à voir le site avant que GitHub ne le construise. Il faut Node.js installé — je ne peux pas vérifier depuis ici si tu l'as, donc commence par ouvrir un terminal dans C:\Users\APina\repere\mono et taper node -v. Si ça répond un numéro de version, tu l'as.

cd C:\Users\APina\repere\mono
npm install -g pnpm
pnpm install
node scripts/extract-html.js ../app_repere_v18_20.html ./data
pnpm test
pnpm build
xcopy /E /I /Y data apps\web\dist\data
node scripts/empreinte-sw.mjs apps/web/dist
npx serve apps/web/dist

La dernière ligne ouvre une adresse locale à coller dans ton navigateur.

Le contrôle dans le navigateur (node tests/runtime.test.mjs apps/web/dist) demande en plus npx playwright install chromium, soit environ 150 Mo de téléchargement. La chaîne GitHub le fait déjà pour toi à chaque run : c'est vraiment facultatif.

Résumé s'il ne fallait retenir qu'une chose : pousser.bat, puis créer build-publish.yml sur GitHub en collant le contenu de docs\build_publish_workflow.yml.txt, puis « Run workflow ». Rien d'autre.
